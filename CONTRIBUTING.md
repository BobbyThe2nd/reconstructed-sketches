# Contributing

Thanks for improving `reconstructed-sketches`.

## Scope

Useful contributions clarify the visual system: a better construction rule, a new subject-specific application, an example brief, or a correction that prevents a known failure mode. Keep the repository centered on recognizable subjects, controlled spatial inconsistency, simple geometry, and hand-drawn restraint.

## Before opening a pull request

1. Make the smallest focused change that solves the problem.
2. Use direct, reusable guidance rather than style-name references.
3. Cross-link related guides when it helps someone follow the workflow.
4. Check that every Markdown link points to an existing local file.
5. Add or update an example if your rule is hard to understand without one.

## Writing conventions

- Use sentence-case headings and concise paragraphs.
- Explain both the rule and the visual reason for it.
- Prefer measurable ranges where practical, such as “two to four interventions.”
- Put prohibitions in `docs/guides/NEGATIVE_RULES.md`; keep positive instructions in the closest relevant guide.
- Do not add generated images, large binaries, or unlicensed reference material.

## Pull request checklist

- [ ] The subject remains recognizable under the proposed rule.
- [ ] The spatial behavior is controlled rather than random.
- [ ] The change supports handmade, non-photoreal rendering.
- [ ] Links and required guide files still validate.
